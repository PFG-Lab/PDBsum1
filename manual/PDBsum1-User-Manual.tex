\section*{What it does}
Give PDBsum1 a PDB file (crystal structure, docking result or model) and it builds a set of linked web pages summarising it: the chains and their secondary structure, \textbf{ligand pages with a LIGPLOT} of every hydrogen bond and hydrophobic contact, \textbf{protein--protein interfaces}, surface \textbf{clefts} (possible pockets) and quality checks (Ramachandran plot). A 2-chain structure with a ligand takes about a minute.

\section*{How to use it}
You need SSH access to the lab VM (ask Dr.~Bilal for the address and login).

\textbf{1. Log in and go to the tool}
\begin{cmd}
ssh <your-login>@<lab-vm-address>
cd /mnt/bilal/pdbsum1
\end{cmd}

\textbf{2. Get your PDB file onto the VM} --- from your own computer, in a second terminal:
\begin{cmd}
scp myprotein.pdb <your-login>@<lab-vm-address>:/mnt/bilal/pdbsum1/input/
\end{cmd}

\textbf{3. Run it} (on the VM)
\begin{cmd}
./pdbsum1.sh myprotein.pdb
\end{cmd}
Progress lines (``Running \ldots'') scroll by; it ends with ``Results at \ldots''.

\textbf{4. Copy the results to your computer} (from your own computer)
\begin{cmd}
scp -r <your-login>@<lab-vm-address>:/mnt/bilal/pdbsum1/results  ./pdbsum1-results
\end{cmd}
Open \textbf{\file{pdbsum1-results/index.html}} in any browser. No software is needed to view it, and you can zip the folder and send it to colleagues.

\section*{Good to know}
\begin{itemize}
  \item \textbf{Give your run a name.} Add a 4-character code after the file: \texttt{./pdbsum1.sh model7.pdb m7a1}. A file named exactly four characters (\file{1ake.pdb}) uses that name; otherwise runs are numbered \texttt{a001}, \texttt{a002}, \ldots
  \item \textbf{Many structures:} put all the files in \file{input/}, write a text file \file{input/list.txt} with one line per structure (\texttt{file.pdb code}), then run \texttt{./pdbsum1.sh -l list.txt}. All appear on the front page.
  \item \textbf{Long runs:} start \texttt{tmux new -s pdbsum1} before running, so it keeps going if your connection drops (detach: Ctrl-b then d; return: \texttt{tmux attach -t pdbsum1}).
  \item \textbf{Better results:} add a \texttt{TITLE} line (shown on the page) and a \texttt{DBREF} line with the UniProt accession (adds the Pfam domain diagram) to your PDB file. Docking and modelling programs sometimes write non-standard PDB files; if a run fails, check the format first.
  \item \textbf{Big assemblies:} clefts are skipped for structures with more than 4 protein chains. Adding \texttt{-nomaxchn} forces them, but it can take very long.
  \item \textbf{Shared machine:} results accumulate in \file{results/}. Copy what you need and tell Dr.~Bilal before deleting anything.
\end{itemize}

\section*{Reading the results}
Click your structure on the front page. The tabs across the top are: \textbf{Top page} (overview), \textbf{Protein} (secondary structure, Ramachandran, motifs), \textbf{Ligands} (one page per ligand/metal, with the LIGPLOT), \textbf{Prot-prot} (interfaces) and \textbf{Clefts} (surface pockets). In a LIGPLOT, green dashed lines are hydrogen bonds (with distances) and red spokes are hydrophobic contacts; PostScript and PDF versions are provided for papers.

\section*{If something goes wrong}
A working run keeps printing progress; if nothing changes for several minutes, press Ctrl-C and check your input file. If you get a ``permission denied'' from Docker, your account has not been given Docker access yet --- ask Dr.~Bilal. For a missing or empty page, look in that structure's \file{logs/} folder inside \file{results/}. For anything else, send the input file and the \file{logs/} folder to Dr.~Bilal.
